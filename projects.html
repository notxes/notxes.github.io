D&D Campaign Management App

Overview

Built a custom full-stack D&D application focused on campaign management, character creation, player tools, and automation for complex tabletop mechanics. The app is designed around D&D 5.5 / 2024 rules and uses database-driven logic instead of hardcoded assumptions wherever possible.

Technologies Used

  • Next.js and React for the frontend
  • Supabase and PostgreSQL for backend data storage
  • TypeScript for application logic
  • Authentication, protected routes, and role-aware user flows
  • Custom database tables for characters, items, spells, features, achievements, and campaign systems

What I Did

  • Designed and built a multi-step character creator
  • Created database-backed systems for species, classes, backgrounds, spells, inventory, and equipment
  • Implemented character sheet features such as actions, senses, defenses, inventory, and spell display
  • Built logic for campaign-specific rules, item handling, equipment validation, and progression systems
  • Worked through schema migrations, permission issues, frontend bugs, and data consistency problems

Results and Learning Outcomes

This project demonstrates full-stack development, long-term debugging, database design, UI organization, complex rule modeling, and project ownership. It also shows the ability to translate a complicated rules system into structured application logic.

Enterprise Segmented Cybersecurity Homelab

Overview

Designed and built a segmented cybersecurity homelab to simulate enterprise network architecture and real-world attack and defense scenarios. The environment supports both attacker and defender workflows, enabling hands-on practice with network security, monitoring, incident response, and adversary simulation in a controlled lab.

Technologies Used

  • Proxmox for multi-node virtualization
  • OPNsense for firewall, routing, and VPN services
  • VLAN segmentation for isolated network zones
  • Security Onion for monitoring and detection
  • Active Directory for Windows domain simulation
  • Kali Linux for offensive testing and attack simulation
  • Pi-hole for DNS management
  • WireGuard for secure remote access
  • Cisco switching for VLAN and infrastructure configuration

Architecture and Design

  • VLAN 10 → Management Network
  • VLAN 20 → Red Team / Attacker Systems
  • VLAN 21 → Victim Environment with Active Directory and endpoints
  • VLAN 30 → Blue Team / Monitoring Infrastructure
  • VLAN 40 → DMZ / Public-Facing Services
  • VLAN 50 → IoT / Untrusted Devices
  • Inter-VLAN traffic routed through OPNsense and controlled through firewall policies
  • SPAN traffic forwarded to Security Onion for monitoring

Results and Learning Outcomes

This project strengthened my understanding of network segmentation, firewall policy design, traffic flow, trust boundaries, and monitoring visibility. It also helped connect attack simulation to defensive detection and incident response workflows.

Overview

Deployed a Security Onion monitoring environment to observe network traffic across lab segments and better understand SOC workflows such as alerting, traffic analysis, event investigation, and visibility tuning.

Technologies Used

  • Security Onion
  • Zeek
  • Suricata
  • Proxmox
  • Cisco Switch SPAN Port
  • Ubuntu Server

What I Did

  • Installed and configured Security Onion in a standalone lab deployment
  • Configured separate management and monitoring interfaces
  • Used mirrored traffic from selected VLANs to monitor lab activity
  • Reviewed dashboards, alerts, packet capture, and logs
  • Troubleshot interface, SPAN, and visibility issues

Results and Learning Outcomes

This project improved my understanding of how monitoring tools ingest traffic, generate alerts, and support investigations. It also improved troubleshooting skills around mirrored traffic and segmented visibility.
